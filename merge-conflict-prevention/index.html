The loop that never conflicts

Six steps, run in order, every time. Follow it and git push stops being something you brace for.

linux-guy@Ademichaelz
RULE ZERO

Never edit the same file in two places between syncs — not on GitHub's website and on your laptop. Pick one place to edit. Treat GitHub as read-only except through git push. This one habit prevents almost every conflict before it can happen.

STEP A

Pull before you touch anything

Every time you sit down to work — before editing a single file. Brings your local copy up to date with anything that changed on GitHub since you last looked, including edits from another machine.

git pull
STEP B

Check status

Confirms you're on the right branch and starting clean — nothing already staged, nothing already modified, fully in sync with the remote.

git status
STEP C

Make your edits

The only step where content actually changes. Edit the file normally — README, script, whatever it is. Everything else in this loop exists to keep you in sync with the remote.

STEP D

Stage and commit

Committing locally doesn't touch GitHub yet — it's safe, and you can do it as many times as you like before pushing.

git add <file> git commit -m "clear description of what changed"
STEP E

Pull again, right before pushing

The step people skip — and the one that actually prevents conflicts. Time has passed since Step A. Pulling now, with your commit already made, lets Git merge in any new remote changes cleanly instead of your push getting rejected.

git pull
STEP F

Push

Because you just pulled in Step E, this goes through clean almost every time — your local branch already contains everything the remote has.

git push
Then repeat from Step A next time you sit down — this is a loop, not a one-off checklist.

One-time setup: keep history linear

Run this once, on any machine — it applies to every repo from then on. When Step E's pull finds new remote commits, this replays your local commit on top of them instead of creating a merge-commit node, so your history stays a clean straight line.

git config --global pull.rebase true
Pull → Status → Edit → Commit → Pull → Push. Loop back to A.
